# 미션 3 엘리베이터 하강 중단 조사

2026-11-02 (한국 시간)

## 신고

엘리베이터가 끝까지 내려오지 않는다. 사용자는 아래 플레이어 때문에 한 번 멈춘 뒤 플레이어가 이동해도 하강 제한이 남는 상황을 의심한다. 아직 재현 및 원인 확정 전이다.

## 제공 진단에서 확인한 사실

- v87 진단: 600개 샘플, 500개 이벤트. 샘플 구간 599.255초.
- 기록 클라이언트 slot 2, hostSlot 1. 이 값만으로 총 참가 인원은 알 수 없다.
- 프레임 33883 → 68618 진행. 마지막 30개 샘플은 초당 최소 58프레임.
- 이벤트 종류는 HTTP, input-wait, input-resumed. 저장된 input-resumed 중 최대 대기 425ms.
- 제공 로그는 통신/프레임 진단이다. 해당 시점의 미션·구역, 플레이어 좌표, 엘리베이터 객체·충돌 플래그·목표 높이·저장 상태는 없다.
- 따라서 게임 전체가 지속적으로 정지했다는 증거는 없다. 엘리베이터가 계속 움직여야 할 조건이 충족됐는지는 이 로그만으로 판단할 수 없다. 순간 통신 지연을 엘리베이터 문제의 원인으로 단정하지 않는다.

## 소스 검토 범위와 한계

- 현재 main의 coop/native/five-session.mjs 및 profile.json을 확인하고 로컬 기존 다인 확장 문서와 비교했다.
- 엘리베이터의 원작 움직임/충돌 처리는 네이티브 게임 로직이다. JavaScript 호스트의 단순 타이머 수정으로 해결할 근거는 없다.
- 기존 확장 문서는 탑승 중 actor +28/+2C가 부모 상대 좌표일 수 있음을 경고한다. 화면 좌표 +3C/+40, 부모 +38, 활성 상태를 함께 관찰해야 한다. 상대 좌표가 음수라는 이유만으로 강제 위치 보정을 하지 않는다.
- 기존 elevator-test 언급은 이전 솔로 확장 이력이며 현재 1~5인에서 신고된 상황을 검증한 증거가 아니다.

## 필요한 재현 확인

엘리베이터 아래에 사람이 있는 상태 → 하강 중단 → 해당 사람이 완전히 벗어남 → 하강 재개 여부를 연속 확인한다. 플레이 중인 인원과 사망/컨티뉴 전환도 함께 기록한다. 정확한 구간을 식별할 수 있는 짧은 영상 또는 직전 게임 저장 상태가 필요하다. 현재 JSON은 게임 저장 상태가 아니므로 이 장면을 복원할 수 없다.

재현 뒤에만 충돌 플래그 잔류, 목표 높이 변경, 비활성/추가 플레이어 판정 누락을 구분해 수정한다. 현재 게임 코드는 변경하지 않았으며 해결 완료로 처리하지 않는다.
