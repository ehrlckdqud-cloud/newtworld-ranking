# 미션 3 엘리베이터 하강 중단 조사

2026-11-02 (한국 시간)

## 신고

엘리베이터가 끝까지 내려오지 않는다. 사용자는 아래 플레이어 때문에 한 번 멈춘 뒤 플레이어가 이동해도 하강 제한이 남는 상황을 의심한다. 아직 재현 및 원인 확정 전이다.

## 제공 진단에서 확인한 사실

- v87 진단: 600개 샘플, 500개 이벤트. 샘플 구간 599.255초.
- 기록 클라이언트 slot 2, hostSlot 1. 이 값만으로 총 참가 인원은 알 수 없다.
- 프레임 33883 → 68618 진행. 마지막 30개 샘플은 초당 최소 58프레임.
- 이벤트 종류는 HTTP, input-wait, input-resumed. 저장된 input-resumed 중 최대 대기 425ms.
- 제공 로그는 통신/프레임 진단이다. 해당 시점의 미션·구역, 플레이어 좌표, 엘리베이터 객체·충돌 플래그·목표 높이·저장 상태는 없다.
- 따라서 게임 전체가 지속적으로 정지했다는 증거는 없다. 엘리베이터가 계속 움직여야 할 조건이 충족됐는지는 이 로그만으로 판단할 수 없다. 순간 통신 지연을 엘리베이터 문제의 원인으로 단정하지 않는다.

## 소스 검토 범위와 한계

- 현재 main의 coop/native/five-session.mjs 및 profile.json을 확인하고 로컬 기존 다인 확장 문서와 비교했다.
- 엘리베이터의 원작 움직임/충돌 처리는 네이티브 게임 로직이다. JavaScript 호스트의 단순 타이머 수정으로 해결할 근거는 없다.
- 기존 확장 문서는 탑승 중 actor +28/+2C가 부모 상대 좌표일 수 있음을 경고한다. 화면 좌표 +3C/+40, 부모 +38, 활성 상태를 함께 관찰해야 한다. 상대 좌표가 음수라는 이유만으로 강제 위치 보정을 하지 않는다.
- 기존 elevator-test 언급은 이전 솔로 확장 이력이며 현재 1~5인에서 신고된 상황을 검증한 증거가 아니다.

## 필요한 재현 확인

엘리베이터 아래에 사람이 있는 상태 → 하강 중단 → 해당 사람이 완전히 벗어남 → 하강 재개 여부를 연속 확인한다. 플레이 중인 인원과 사망/컨티뉴 전환도 함께 기록한다. 정확한 구간을 식별할 수 있는 짧은 영상 또는 직전 게임 저장 상태가 필요하다. 현재 JSON은 게임 저장 상태가 아니므로 이 장면을 복원할 수 없다.

재현 뒤에만 충돌 플래그 잔류, 목표 높이 변경, 비활성/추가 플레이어 판정 누락을 구분해 수정한다. 현재 게임 코드는 변경하지 않았으며 해결 완료로 처리하지 않는다.

## 2026-11-03 추가 진단: 미션 4 / 미션 5

v88 두 파일을 로컬에서 분석했다. 원본 파일과 회원별 개인 정보는 저장소에 올리지 않았다.

### 미션 4: 조작자 소유권 이상 확인

- 기록된 4인 세션의 2번 actor(0x1005AC)에서 +0x6C 조작자 번호가 기대값 1이 아닌 0이었다. 1번 actor의 번호도 0이다. 3번/4번은 2/3으로 유지된다.
- 첫 관측 프레임 56556부터 마지막 59965까지 잘못된 번호가 유지된다.
- 프레임 56793 이후 다수 샘플에서 1번/2번의 화면 좌표와 실행 루틴이 일치한다. 단순 렌더링 겹침으로 보기 어렵다.
- 닉네임과 슬롯의 대응은 로그에 없으므로 특정 회원을 1번/2번으로 단정하지 않는다.
- 실제 코어의 1~5인 초기 진입 테스트에서는 조작자 번호 0..N-1이 정상이다.
- 별도 4인 미션 4 직접 진입/동일 입력 30000프레임 fixture에서는 소유권 변경이 재현되지 않았다. 이는 신고 구간 자연 플레이 재현이나 정상 판정이 아니다.
- 기록 시작 전에 이미 이상이 있으므로 최초로 번호를 덮어쓴 명령은 아직 특정하지 못했다. 매 프레임 번호를 강제로 고정하는 우회는 적용하지 않았다.

### 미션 5: 연출 상태 불일치 및 비정상 메모리 패턴 확인

- 4인 세션, 네이티브 mission=4/substage=2.
- 프레임 109806..110813에서 1~3번은 화면 좌표 (96,480), routine 0x25A26에 머무른다. 4번은 (96,304), routine 0x24ED6에 남는다.
- 같은 시점 0x671AA 연출 객체 3개가 존재한다.
- 프레임 110931부터 미션/구역/활성 마스크는 0x55, 진행 루틴과 모든 플레이어 루틴/부모는 0x55555555로 바뀐다. 정상 게임 상태가 아니다.
- 0x55555555 패턴만으로 최초 예외 명령이나 오류 화면 문구를 특정할 수는 없다. 네이티브 초기화/오류 경로도 구분해야 한다.
- 현재 델타의 0x669C4 및 0x66A36은 이전 P3 확장 코드로 이동한다. 원작의 P1/P2 연출 객체 생성과 P3 추가를 확인했다. 이 장면의 P4/P5 처리가 다른 일반 스크립트 확장과 일치하는지 후속 검증이 필요하다.
- 원작부터 P1/P2 각각의 연출 객체를 생성하므로 '두 명이 잡혔다'는 사실만으로 잘못된 분기라고 단정하지 않는다. 납치 대상 선정, 캐릭터 교체, 남은 인원, 후속 준비 완료 조건을 함께 확인해야 한다.

### 미션 3 신고 정정

사용자가 처음 하강부터 끝까지 내려오지 않는다고 명확히 했다. 최초 아래 플레이어 충돌이 원인이라는 가설은 미확정으로 유지한다. 두 추가 파일의 game 구간은 미션 4/5이며 미션 3의 엘리베이터 객체를 포함하지 않는다. 초기 높이/하강 종점/활성 플레이어 열거를 재현 검사할 대상이다.

### 상태

두 추가 장애의 실제 상태 이상은 확인했지만 최초 원인 명령 및 안전한 수정은 아직 검증 전이다. 이번 조사에서 게임 동작 패치를 배포하지 않았다. 이전 통신 지연 문제 해결이나 v88 진단 배포를 이 세 장애의 해결 완료로 취급하지 않는다.
