# 포인트·외부 운영자 이용권 v1

## 배포와 운영

비공개 newtworld-automation 서버 PR을 먼저 배포한 다음 화면 PR을 배포합니다.
처음에는 `준비 중`이며 운영자가 메인 관리자 메뉴 → 포인트·외부 고객 관리에서 설정을 확인합니다.
기본값: 최초 보상 1,000 P / 일반 마블 100 P. 모두 숫자로 변경 가능합니다.
기간형은 24시간 단위 일수, 횟수형은 실제 시작 요청 횟수입니다.
일수 추가는 max(현재 시각, 기존 만료 시각) 기준입니다. 방식 변경은 기존 이용권을 대체합니다.
럭키 팩토리, 생존연못, 우주대탈출은 서버에서 관리자 전용으로 고정합니다.
이벤트 후 별도 검토한 변경으로 공개해야 하며 날짜만으로 자동 공개되지 않습니다.

## 회원 포인트

첫 운영 전환 당시 재실 회원별 영구 누적 점수를 기준값으로 보관합니다.
그 이후 누적 점수 증가분을 내페이지 조회/실행 시 자동 정산합니다.
시작 후 새로 확인되는 회원은 첫 지갑 조회 시점을 기준으로 합니다.
과거 누적 점수 소급 지급은 하지 않습니다. 월별 점수 초기화와 무관하게 누적 점수를 사용합니다.
정정으로 누적 점수가 감소해도 자동 회수하지 않으며 이전 최고 지급 기준을 회복할 때까지 중복 적립하지 않습니다.
잘못된 집계에 대한 포인트 정정은 관리자 지급/회수 화면에서 사유와 함께 처리합니다.
랭킹 점수는 포인트 소비로 감소하지 않습니다.

## 외부 고객

입금 확인 → 고객 등록(이름/이메일/기간 또는 횟수/수량) → 초대 링크 발급 → 등록 이메일로 운영자가 직접 전달.
이 버전은 이메일 자동 발송/이메일 OTP 본인확인을 구현하지 않습니다. 초대 링크를 가진 사람이 초대를 수락하므로 공개 채널에 링크를 올리지 마세요.
24시간 단회 링크, 기기별 토큰 해시 저장, 30일 세션. 재발급하면 이전 기기 세션을 폐기합니다.
외부 고객은 뉴트월드 랭킹/회원 사진 API 권한을 부여받지 않습니다.
참가자 명단·결과는 기존 게임처럼 브라우저 로컬 보관이며 마블의 키를 이용자별로 분리합니다.
서버에 고객별 명단/결과를 동기화하는 기능은 이번 범위에 포함되지 않습니다.

## 거래와 오류 처리

서버의 ScriptLock 안에서 요청ID와 변경된 지갑 상태를 한 원장 행에 함께 기록합니다.
응답 지연 재시도는 같은 요청ID를 사용합니다. 클라이언트가 보낸 가격은 사용하지 않습니다.
시작 전 입력/미디어 준비 실패는 차감 전 처리합니다. 승인 후 브라우저 종료·실행 실패는 관리자 확인 후 수동 반환합니다.
원장에는 전체 내역, 내페이지에는 최근 10건을 보여줍니다. 화면용 상태에는 최근 50건을 유지합니다.
이용량이 커지면 전체 원장 검색을 하는 초기 구현을 DB 트랜잭션/인덱스로 이전해야 합니다.

## 검증 및 중요한 한계

Apps Script 기존 회귀검사 + 새 서버 거래/권한 모의 테스트 통과.
브라우저 UI 테스트는 `node tests/content-access.cjs` (playwright + chromium, localhost:8765 필요).
Google Apps Script 실제 POST 응답/휴대폰 화면/운영 시트는 PR 배포 뒤 별도 확인해야 합니다.
공개된 정적 JS 게임은 복제/변조 실행을 서버에서 막을 수 없습니다. 이 구현은 공식 화면의 정상 실행에 대한 거래 통제입니다.
결과 보상, 도박/현금 결제, 복제 방지 또는 상용 수준의 강제 과금 보안을 제공하지 않습니다.
상용 대여 전 게임 전달을 인증된 서버로 옮기고 실행/결과 검증 구조를 추가해야 합니다.
