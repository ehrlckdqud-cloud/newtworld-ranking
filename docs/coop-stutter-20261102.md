## 진단 근거
첨부 newtworld-v82-diagnostics-2026-10-31T08-44-12.254Z.json: 이벤트 500개, 프레임 샘플 600개. 샘플 초당 진행 프레임 38~60, 통상 59~60. input-wait 8건, render-gap 2건(194/756ms), HTTP timeout 8건, ROOM_BUSY_RETRY 4건, CONTINUE_NOT_AVAILABLE 31건. 이벤트는 여러 세션에 걸쳐 있으며 모든 HTTP 지연과 화면 정지를 동일 원인으로 단정할 수 없다. 샘플 최저 38은 측정 구간의 진행 프레임이며 GPU FPS 측정치가 아니다.

## 현재 코드와 차이
현재 main에는 v85 컨티뉴 개선, v86 입력 즉시 처리/진단 보강과 결과 화면 캐시가 이미 존재했다. 첨부는 v82이므로 최신 코드의 모든 문제를 입증하지는 않는다.

## 수정
- catch-up 루프의 5프레임 개수 제한에 8ms 실행 시간 예산을 추가했다. 프레임은 완전히 실행한 후 양보하므로 단일 프레임이 8ms보다 길 수 있다. 한 프레임 자체의 성능 문제를 해결하는 하드 실시간 제한은 아니다.
- 느린 프레임을 연속 5개 실행하여 RTC 입력 수신/키보드 이벤트를 막는 증폭 경로를 완화한다. 프레임/명령을 버리지 않으며 프로토콜은 유지한다.
- 활성 게임 중 JSON 직렬화/localStorage 동기 저장을 중지했다. 진단은 메모리에 계속 수집되며 다운로드 가능하고 비플레이 상태/페이지 이탈 때 저장한다. 비정상 브라우저 종료 시 마지막 활성 세션 기록은 소실될 수 있다.
- 진단 버전87 및 진입 모듈 캐시 키 변경.
